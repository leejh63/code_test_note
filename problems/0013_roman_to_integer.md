## 1. 간단 문제 설명

로마 숫자로 표현된 문자열 `s`를 정수로 변환하는 문제이다.

| 문자 | 값 |
|---|---:|
| I | 1 |
| V | 5 |
| X | 10 |
| L | 50 |
| C | 100 |
| D | 500 |
| M | 1000 |

일반적으로 큰 값부터 작은 값 순으로 배치하여 모두 더한다.

```text
VIII = 5 + 1 + 1 + 1 = 8
```

단, 다음 6개 조합은 앞의 작은 값을 뒤의 큰 값에서 빼는 형태로 사용한다.

```text
IV = 4
IX = 9
XL = 40
XC = 90
CD = 400
CM = 900
```

예:

```text
MCMXCIV
= M + CM + XC + IV
= 1000 + 900 + 90 + 4
= 1994
```

## 2. 내가 진행한 코드 및 부족한 부분

### 내가 처음 작성한 코드

문제에서 제시한 6개의 뺄셈 조합을 직접 검사하는 방식으로 구현했다.

```c
int romanToInt(char *s)
{
    int str_ind = 0;
    int number = 0;
    char roman = s[str_ind];

    while (roman)
    {
        if (roman == 'I')
        {
            if (s[str_ind + 1] == 'V')
            {
                number += 4;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            if (s[str_ind + 1] == 'X')
            {
                number += 9;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            number += 1;
        }
        else if (roman == 'V')
            number += 5;

        else if (roman == 'X')
        {
            if (s[str_ind + 1] == 'L')
            {
                number += 40;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            if (s[str_ind + 1] == 'C')
            {
                number += 90;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            number += 10;
        }
        else if (roman == 'L')
            number += 50;

        else if (roman == 'C')
        {
            if (s[str_ind + 1] == 'D')
            {
                number += 400;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            if (s[str_ind + 1] == 'M')
            {
                number += 900;
                str_ind += 2;
                roman = s[str_ind];
                continue;
            }

            number += 100;
        }
        else if (roman == 'D')
            number += 500;

        else if (roman == 'M')
            number += 1000;

        roman = s[++str_ind];
    }

    return number;
}
```

### 접근 방법

문제에 명시된 예외 조합을 그대로 코드로 옮겼다.

```text
IV → +4
IX → +9
XL → +40
XC → +90
CD → +400
CM → +900
```

이 방식도 정상적인 풀이이며 문자열을 한 번 순회하므로 시간 복잡도는 `O(n)`이다.

### 부족한 부분

성능 자체가 큰 문제는 아니지만 코드 구조를 더 단순화할 수 있다.

- 6개의 예외를 각각 조건문으로 처리한다.
- `I`, `X`, `C`에서 비슷한 조건문이 반복된다.
- 두 글자 조합을 처리하기 위해 `str_ind += 2`, `continue` 등 인덱스를 직접 관리한다.
- 6개의 예외가 가지고 있는 공통 규칙을 일반화하지 못했다.

즉, **개별 예외를 하나씩 처리하는 방식**이다.

## 3. 참고한 풀이에서 얻은 개선 아이디어

> 이 절에서는 LeetCode에서 확인한 다른 풀이의 코드를 그대로 기록하지 않고,  
> 풀이를 통해 이해한 핵심 아이디어만 정리한다.

### 참고 풀이 A — 뒤에서 앞으로 순회

한 참고 풀이에서는 문자열의 길이를 먼저 구한 뒤 마지막 문자부터 앞으로 이동했다.

핵심은 다음과 같다.

```text
1. 마지막 로마 숫자는 우선 더한다.
2. 현재 값과 오른쪽 값을 비교한다.
3. 현재 값 < 오른쪽 값이면 현재 값을 뺀다.
4. 그렇지 않으면 현재 값을 더한다.
```

예:

```text
IV

오른쪽 V = 5 → +5
왼쪽 I = 1

1 < 5
→ -1

결과 = 4
```

이 방식에서 배운 점은 `IV`, `IX`, `XL`, `XC`, `CD`, `CM`을 각각 별도 처리하지 않고 **값의 크기 비교로 공통화할 수 있다는 것**이다.

---

### 참고 풀이 B — 앞에서 뒤로 순회

다른 참고 풀이에서는 문자열의 처음부터 끝까지 이동하면서 현재 값과 다음 값을 비교했다.

핵심은 다음과 같다.

```text
현재 값 < 다음 값
→ 현재 값을 뺀다.

현재 값 >= 다음 값
→ 현재 값을 더한다.
```

예:

```text
IV
→ -1 + 5
→ 4

IX
→ -1 + 10
→ 9

CM
→ -100 + 1000
→ 900
```

앞에서부터 읽더라도 뺄셈 표기의 작은 값을 먼저 음수로 반영하면 같은 결과를 얻을 수 있다.

---

### 두 참고 풀이에서 공통으로 얻은 핵심

두 방식은 순회 방향은 다르지만 결국 같은 규칙을 이용한다.

```text
작은 값이 큰 값 바로 앞에 있는 경우
→ 작은 값을 빼기

그 외
→ 값을 더하기
```

따라서 처음 작성한 코드처럼 6개의 조합을 각각 직접 검사할 필요가 없다.

## 4. 개선된 코드

### 학습용 재구성 코드

아래 코드는 참고 풀이의 코드를 그대로 옮긴 것이 아니라,  
위에서 이해한 공통 규칙을 기준으로 다시 구성한 코드이다.

```c
static int roman_value(char c)
{
    switch (c)
    {
        case 'I': return 1;
        case 'V': return 5;
        case 'X': return 10;
        case 'L': return 50;
        case 'C': return 100;
        case 'D': return 500;
        case 'M': return 1000;
        default:  return 0;
    }
}

int romanToInt(char *s)
{
    int total = 0;

    for (int i = 0; s[i] != '\0'; ++i)
    {
        int current = roman_value(s[i]);
        int next = roman_value(s[i + 1]);

        if (current < next)
            total -= current;
        else
            total += current;
    }

    return total;
}
```

### 기존 코드와 차이

- 기존: 6개의 뺄셈 조합을 각각 조건문으로 처리
- 개선: 현재 값과 다음 값의 대소 관계라는 공통 규칙으로 처리
- 기존: 두 글자를 처리할 때 인덱스를 직접 2칸 이동
- 개선: 한 문자씩 순서대로 이동
- 개선 효과: 조건 분기와 인덱스 관리가 줄어 구조가 단순해짐

### 복잡도

- 시간 복잡도: `O(n)`
- 공간 복잡도: `O(1)`

문자열을 한 번 순회하고 입력 크기에 비례하는 별도 자료구조를 사용하지 않는다.

## 5. 질문 사항과 답

### Q1. `current < next`이면 현재 값을 빼는 방식이 어떻게 가능한가?

**A.**

로마 숫자의 뺄셈 표현을 다음처럼 바꿔 생각할 수 있다.

```text
IV = 5 - 1
```

이를 덧셈 형태로 보면:

```text
-1 + 5 = 4
```

이므로 왼쪽부터 읽으면서 현재 값보다 다음 값이 크다면 현재 값을 빼도 같은 결과가 나온다.

```text
IV = -1 + 5 = 4
IX = -1 + 10 = 9
XL = -10 + 50 = 40
XC = -10 + 100 = 90
CD = -100 + 500 = 400
CM = -100 + 1000 = 900
```

따라서 6개의 예외를 각각 처리하는 대신 하나의 공통 규칙으로 처리할 수 있다.

---

### Q2. 그러면 `IM`처럼 `I` 뒤에 `M`이 있으면 빼면 안 되는 것 아닌가?

**A.**

맞다.

실제 로마 숫자 규칙에서는 작은 숫자 뒤에 큰 숫자가 있다고 해서 항상 뺄 수 있는 것은 아니다.

허용되는 뺄셈 조합은 다음 6개뿐이다.

```text
IV
IX
XL
XC
CD
CM
```

따라서 다음과 같은 표기는 유효하지 않다.

```text
IM
IL
XD
XM
```

단순 비교 방식에서는 `IM`을 계산하면 `999`가 나오지만, `IM` 자체가 올바른 로마 숫자가 아니다.

이 문제에서는 입력이 항상 유효한 로마 숫자라고 보장되므로:

```text
current < next
```

인지만 검사해도 된다.

즉:

```text
실제 로마 숫자 전체 규칙
→ current < next라고 항상 뺄 수 있는 것은 아님

이 LeetCode 문제
→ 입력이 이미 유효하다고 보장됨
→ current < next 비교만으로 충분함
```

### Q3. 뒤에서 앞으로 푸는 방식과 앞에서 뒤로 푸는 방식에서 왜 실행시간 차이가 발생하는가?

**A.**

두 방식 모두 이론적인 시간 복잡도는 `O(n)`이다.

#### 뒤에서 앞으로 순회하는 참고 방식

문자열 길이를 먼저 구한 뒤 역순으로 이동한다.

```text
문자열 길이 계산 → O(n)
문자열 순회      → O(n)

전체 → O(n) + O(n)
     → O(n)
```

#### 앞에서 뒤로 순회하는 참고 방식

문자열의 종료 문자 `'\0'`를 확인하면서 바로 순회할 수 있다.

```text
문자열 순회 → O(n)
```

따라서 실제 수행하는 연산 수에는 어느 정도 차이가 생길 수 있지만, Big-O 기준에서는 둘 다 `O(n)`이다.

또한 구현 방식에 따라 같은 로마 문자를 숫자로 변환하는 함수를 반복 호출하는 횟수 등에서도 작은 차이가 생길 수 있다.

하지만 이 문제는 문자열 길이가 최대 15이므로 입력 자체가 매우 작다.

따라서 LeetCode에서 나타나는 작은 실행시간 차이만으로:

```text
A 방식이 확실히 더 빠르다
B 방식이 확실히 더 빠르다
```

라고 판단하기는 어렵다.

정리하면:

```text
뒤→앞 순회 : O(n)
앞→뒤 순회 : O(n)

실제 명령 수에는 차이가 있을 수 있음
하지만 입력 크기가 매우 작음
→ 작은 ms 차이는 알고리즘 우열을 의미하지 않음
```

이 문제에서는 실행시간 숫자보다 **코드 구조가 얼마나 단순하고 이해하기 쉬운가**를 보는 것이 더 적절하다.

# 부록

## A. 같은 값 변환을 반복하지 않기

다음과 같이 현재 값과 다음 값을 먼저 변수에 저장하면 같은 변환을 반복할 필요가 없다.

```c
int current = roman_value(s[i]);
int next = roman_value(s[i + 1]);
```

그 뒤에는:

```c
if (current < next)
    total -= current;
else
    total += current;
```

처럼 사용할 수 있다.

성능 차이보다 코드의 의미가 명확해지는 장점이 크다.

---

## B. `if-else`와 `switch`

로마 문자 값을 변환할 때 `if-else`와 `switch` 모두 사용할 수 있다.

둘 중 하나가 항상 더 빠르다고 단정할 수는 없다.

컴파일러는 조건의 형태와 최적화 방식에 따라 내부 코드를 다르게 생성할 수 있기 때문이다.

이 문제에서는 입력이 매우 작으므로 성능 차이보다는 읽기 쉬운 형태를 선택하는 것이 적절하다.
